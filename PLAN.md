# Школа №165 — онлайн-тестування

Проєкт розміщується в `D:\laragon\www\school`. Для першої версії підійдуть PHP з PDO та MySQL у Laragon. Назва бази — `school`, кодування — `utf8mb4`. Прикріплений макет задає вигляд учнівської сторінки.

## Як проходитиме тестування

- Учень обирає свій клас, предмет і тему, вводить ім’я та проходить опублікований тест. У першій версії окремі учнівські акаунти не потрібні.
- Учитель входить за логіном і паролем, створює чернетку тесту, додає запитання, варіанти й правильні відповіді, після чого публікує тест для вибраного класу.
- Сервер автоматично оцінює запитання з одним або кількома правильними варіантами. Для множинного вибору повний бал нараховується за точний збіг набору відповідей.
- Розгорнуті відповіді зберігаються для перевірки вчителем. Після надсилання учень бачить статус «Очікує перевірки». Якщо всі запитання автоматичні, оцінка доступна одразу.
- Учитель бачить список спроб і фільтрує його за класом, предметом, тестом, датою та статусом. У деталях спроби видно відповіді й бали за кожне запитання.

## Таблиці

| Таблиця | Основні поля та призначення |
| --- | --- |
| `teachers` | `id`, унікальний `login`, `password_hash`, `display_name`, `is_active` |
| `classes` | `id`, `grade`, `section`. Унікальна пара паралелі й літери, наприклад 8-А |
| `subjects` | `id`, унікальна `name`, наприклад «Інформатика» |
| `tests` | `id`, `subject_id`, `teacher_id`, `title`, `status`, `previous_test_id`, `published_at`. Назва тесту може бути назвою теми, наприклад «Бази даних і СУБД» |
| `test_classes` | `test_id`, `class_id`. Складений ключ дозволяє призначити один тест кільком класам |
| `questions` | `id`, `test_id`, `type` (один варіант, кілька або розгорнута відповідь), `prompt`, `max_points`, `position`, `grading_guidance` для вчителя |
| `question_options` | `id`, `question_id`, `label`, `is_correct`, `position` |
| `attempts` | `id`, `test_id`, `class_id`, `student_name`, `status`, `started_at`, `submitted_at`, `graded_at`, `earned_points`, `max_points`, `grade` |
| `attempt_answers` | `id`, `attempt_id`, `question_id`, `written_answer`, `awarded_points`, `graded_by`. Одна відповідь на пару «спроба + запитання» |
| `attempt_answer_options` | `answer_id`, `option_id`. Складений ключ зберігає вибрані варіанти без дублікатів |

Після публікації запитання, варіанти та максимальні бали фіксуються. Для змін учитель створює нову редакцію тесту через копію чернетки. Архівна редакція залишається доступною у звітах разом зі старими спробами.

Пропонована формула оцінки — `max(1, round(12 × набрані бали / максимальні бали))`. Наприклад, 12 із 15 дають оцінку 10. Публікація тесту без запитань або з некоректними ключами відповідей забороняється.

## Етапи створення

1. **База та запуск у Laragon.** Підготувати SQL-міграцію із зовнішніми ключами й індексами для звітів, локальні налаштування підключення та команду створення першого вчителя з хешованим паролем.
2. **Кабінет учителя.** Зробити вхід, вихід і перевірку сесії для всіх учительських маршрутів. Додати керування класами, предметами, тестами, запитаннями й варіантами. Перевіряти дані на сервері та захищати форми від CSRF.
3. **Учнівська сторінка за макетом.** Зверстати каталог із фільтрами та картками, екран проходження тесту з прогресом і екран результату. Перевірити вигляд на телефоні.
4. **Збереження та оцінювання.** Надсилати відповіді одним завершенням спроби, записувати їх і автоматичні бали в транзакції, відхиляти повторне надсилання тієї самої спроби. Додати перевірку відкритих відповідей у кабінеті та перерахунок оцінки.
5. **Звіти й наскрізна перевірка.** Додати фільтри й деталі спроби. Перевірити шлях від створення тесту до остаточної оцінки, доступ до кабінету, повторне надсилання та збереження історії після публікації нової редакції.
